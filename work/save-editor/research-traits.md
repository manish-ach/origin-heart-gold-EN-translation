# Origin v4.0.3 party traits: native verification

Read-only disassembly of the local Chinese reference ROM and English build on 2026-10-04 with ndspy/capstone. No downloads. Addresses below are ARM9 runtime addresses. Verified relevant signatures identical in both builds.

## Shiny

- Getter dispatch field `0xBD` targets `0x0206DC2C`: u32 logical block B+0x14 bit31. Signature `6869c40f98e1`.
- Setter `0x0206E394` preserves lower31 bits and replaces bit31 using input low bit. Signature `6969da4814b001402078c00708436861f8bd`.
- `0x0206F3F8` returns true immediately for override1, otherwise reads OT ID (field7, A+4 u32) and PID (field0), then calls `0x0206F42C`.
- Natural shininess is XOR of PID low/high halfwords and OT low/high halfwords <8; comparison at `0x0206F444`.
- Safe enabling: set override bit. Clearing override does not disable naturally shiny Pokémon. Do not rewrite PID to force removal: it also determines block permutation and party-tail encryption and affects personality-derived properties.
- Preserve lower31 bits of B+0x14, especially nature override bits25..30.

## Pokérus

- Getter field `0x9A` targets `0x0206DE7C`, reads u8 logical D+0x1A. Signature `8c7e71e0`.
- Setter `0x0206E754` writes only that byte. Signature `207814b0b076f8bd`.
- Active getter `0x02070CF0`: low nibble nonzero. Signature `08b59a210022fcf727fe0f21084201d0012008bd002008bd`.
- Cured getter `0x02070D10`: low nibble zero and high nibble nonzero. Signature `08b59a210022fcf717fe0006010e0f20084201d0002008bdf020084201d0012008bd002008bd`.
- Day reduction `0x02070C9C..0x02070CD8`: ignores zero low nibble, otherwise subtracts elapsed days; if elapsed days exceed remaining duration or four, clears low nibble. Preserves high nibble; replaces resulting zero byte with0x10.
- Thus byte0 is none; high nibble is strain/history, low nibble duration; active/cured/none is a three-state UI, not a boolean.
- The bounded investigation did not locate the random infection generator or prove the EV multiplier path. Do not claim native generation strain/duration rules or EV bonus verification based only on these getters. Byte0x11 is active to the verified native getter and expires to0x10 after one elapsed day.

## Runtime verification

`scripts/verify-runtime.py --expect-traits traits.json --persistence` independently decrypts complete bounded native party records, compares shiny/override/natural status and Pokérus raw/strain/days/status at load and reset/reload, and checks native code signatures before starting. It reuses existing save-counter, checksum, ownership, identity, heap and input-preservation guards. STAT_FIELDS and stat decoder output are unchanged.

Expected JSON is an array, one entry per party member: `{ "shiny": true, "naturalShiny": false, "shinyOverride": true, "pokerus": { "raw": 17, "strain": 1, "days": 1, "status": "infected" } }`.

Use `--observe-traits` to navigate every party summary and collect actual native helper return values. Entry/return hooks are bounded to the live party owner, exact slot address, PID and call stack. They read registers/memory only. The summary short-circuits the infected helper when cured is true; cured=true is sufficient evidence for those slots. Pending hook contexts are discarded at reset.

Final EN result: `local/traits-runtime-en-fresh/report.json` passed with zero gaps, native save counter9→10, strict raw traits, stats and moves matching at load and reset/reload. Independent phase audit of recorded callbacks:25 calls before reset and23 after reload. In both phases all six shiny results matched (slots0/2 true); slots0/3 returned infected=true,cured=false; slots1/4 cured=true; slots2/5 returned bothfalse. Slot0 screenshots visibly show both the shiny star and PKRS badge. Source ROM/save hashes unchanged.

Initial old-date fixtures immediately cured on boot through the game's normal elapsed-day processing. This was retained as exploratory evidence under `local/traits-runtime-en*`. The final fixture was generated by applying the editor's public codec to a fresh native save export (`local/traits-fresh-fixture`), without altering RTC or weakening raw-byte expectations. Date-based curing is expected behavior, not a persistence failure. Early navigation trials also identified the need to move UP once from the remembered Pokémon menu cursor before opening SAVE.

Native propagation/EV-bonus behavior during battle remains unverified.
